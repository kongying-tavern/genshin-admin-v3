# 瓦片缓存读取基准

在仓库根目录运行 `node scripts/tile-cache-bench/serve.mjs`，用 Chromium 打开终端打印的回环地址，点击「开始」。服务使用临时端口，不需要应用配置或后端。关闭终端里的服务即可停止。地址加上 `?tiles=16&rounds=2&handles=8&autorun=1` 可运行短测。自动化可等待 `#status[data-state="done"]`，并读取 `#results`。

默认生成 256 张确定性的 256 × 256 PNG。同一批字节预写入 Cache Storage 和 OPFS。服务端对瓦片路径返回 404，因此 `fetch` 成功只能来自接管页面的基准 Service Worker。每个模式分别对顺序和随机访问预热一次，再测量五轮。随机访问使用固定种子，每轮访问每张瓦片一次，各模式使用相同顺序。基准结束后释放句柄、删除本轮 Cache Storage 和 OPFS 目录，并注销基准 Service Worker。

| 模式 | 计入耗时的操作 |
| --- | --- |
| Service Worker → Cache API | 页面 `fetch`、SW 打开命名库并按 URL 匹配，以及页面消费全部响应字节 |
| OPFS 异步 | 复用父目录句柄，逐瓦片取得文件句柄及 `File`，读取为 `ArrayBuffer` |
| OPFS 同步，复用句柄 | 专用 Worker 按最近访问顺序复用有限数量的同步句柄和文件长度，读满缓冲区并转移给页面 |
| OPFS 同步，每次打开 | 专用 Worker 每次获取并关闭同步句柄，其余读取和数据转移相同 |
| Cache API 直读 | 页面从已打开的 Cache Storage 库匹配，并消费全部响应字节 |

表格的轮耗时、p50/p95/p99 和吞吐按页面端到端读取计算。Worker 列是各轮 Worker 内累计耗时的中位数除以瓦片数，覆盖句柄获取或复用、缓冲区分配及读取。另列计时段的同步句柄打开总数。默认的 256 个句柄可容纳整个工作集，预热后打开数应为 0。把句柄上限调小可以观察淘汰后重新打开的成本。每次淘汰会先关闭旧句柄，切换模式和运行完毕也会关闭持有的句柄。

测量范围是已缓存瓦片的原始字节读取，包含逐瓦片的 Worker 通信，排除样本生成、写入、预热和图像解码。系统文件缓存可能已预热。精度受浏览器计时器步长影响，单次耗时显示为 0 时，仍可比较多次读取的轮耗时。比较不同设备时请记录浏览器版本、瓦片大小和句柄上限。
